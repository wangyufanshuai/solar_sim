## Interpretation and stop conditions

Separate measured guard cost from an inference about the old timeout. Static
source shows the 43-row exact matrix-product loop calls its guard on rows
0,8,16,24,32,40, and the parent monitor also scans between its 50 ms sleeps.
These explain amplification opportunities, not measured counts/time shares
of the old run. No matrix product is executed in this diagnostic.

Actual directory shapes differ in both file count and nesting; cross-target
comparisons do not isolate one variable. Warm metadata, background disk load,
the independently active supervisor and profiler overhead are confounders.
Never present a scan/guard ratio from separate samples as an exact historical
percentage, nor claim a projected speedup has already been achieved.

If a hotspot is supported, propose an additive, rollback-safe optimization
that retains the deadline, byte-cap checks before writes, disk floors,
independent monitor, stop propagation and durable failed terminals. Do not
implement that optimization or rerun eight rays under this authorization.
Freeze this plan at execution; results belong in a separate post-run report.
