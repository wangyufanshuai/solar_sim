# 单次全量扫描候选：等价域与安全验收方案

## Material Passport

- Origin Skill: academic-research-suite / experiment-agent.
- Origin Mode: measured-diagnosis follow-up proposal，非已批准新实验。
- Origin Date: 2026-10-13，Asia/Shanghai。
- Verification Status: UNVERIFIED optimization proposal；尚无候选实现或加速结果。
- Version Label: guard_scan_equivalence_plan_v1.

## 决策

优先优化**每次完整扫描内部的重复工作**，保持原检查调用点、磁盘查询、
写入前配额检查和独立监护循环不变。不从降低频率、放宽限额、缓存旧总量
或延长科研预算开始。

依据是已完成的
[137 秒诊断](E:/86137/myai/solar_sim/next-web/science/numerical_relativity/RESULTS-20261013-guard-overhead-diagnostic.md)：
旧超时目录上的 guard 中位耗时 309.481 ms；三次剖析中扫描区段占 guard
累计时间约 99.88%。这支持优化目标，不保证某个候选的加速幅度，也不证明
优化后八射线一定能完成。

## 候选设计，不改旧源码

1. 新增独立扫描器和可回滚预算类，不覆盖冻结的
   `scripts/nr_owned_control.py`，不改任何科学方程、数据或旧回执。
2. 每次调用重新从已确认的输出根目录出发，以显式栈作单次目录遍历。
   每个目录只枚举一次，不使用递归 glob 与通配选择器的双层枚举。
3. 对每个条目取得一次**新鲜的**状态，统一判断类型与逻辑字节数；
   不先 is_file 再重复 stat。第一候选优先用新 os.stat/lstat 读取，
   不依赖先前缓存的大小，特别是仍在增长的工作日志。
4. 每次检查使用新的目录迭代器并及时关闭；不跨检查保存 DirEntry，
   不保存可直接跳过重新检查的目录总量。
5. 保留原头尾时限检查，并设计扫描内部的有界停止检查，避免大目录让
   一次扫描长时间不响应。新增检查只能提前保守停止，不延长截止时间。
6. 使用既有 supervisor 的 budget_factory 注入接口接入候选；独立监护
   生命周期、Job Object、启动握手、进程清理及预分配终态机制不变。
   工作进程和监护进程必须使用同一明确记录的候选版本，不静默混用。

Python 文档说明目录项状态可能缓存，动态目录的枚举也不是原子快照；
因此“用 scandir”不等于自动获得安全等价。最新状态应重新获取。
[Python 3.12 scandir / DirEntry](https://docs.python.org/3.12/library/os.html#os.scandir)

本方案沿用有界监护模型，不声称扫描可以在任意并发写入下提供原子、
全局瞬时的字节快照。写入前预算与独立监护仍是必需的互补保护。

## 明确等价适用域

正常等价域：根目录已建立且可读，条目都是普通目录或普通文件，
没有重解析点、符号链接、特殊文件或扫描期间变动。

在这个域内，要求候选与旧实现：

- 遍历同一完整相对路径集合，逻辑字节总数逐字节一致。
- 同名、空文件、深层目录、Unicode、隐藏文件、文件扩展名不影响计数。
- 硬链接仍按每个目录项计数，不能擅自去重成物理分配字节。
- 配额判断保留 used + additional + headroom 与 cap 的原边界，
  等于上限和超出一字节的结果必须与旧实现一致。
- 磁盘底线、时限及异常传播合同不变，不引入静默重试。

异常域必须另列，不能冒充字面行为等价：本机 Python 3.12.3 的
`pathlib.py` 中，通配遍历会忽略部分 OSError，walk 默认也会跳过部分
枚举错误。这是本轮源码审计发现的风险，不是观测到本次预算失守。
候选应对无法读取、条目/目录意外消失、越界路径、链接/重解析点和
无法确定的文件类型保守停止，而不是把缺失部分当作零字节。
这种更严格的停止行为应明确记录为安全强化并测试，不能称其与旧异常
处理逐分支相同。

创建前允许根目录不存在与运行中根目录意外消失，必须由生命周期状态
明确区分，不能单凭 exists 返回 false 就一律认定零占用。

## 下一批候选验证的建议范围

需要新的明确授权后才能实现并执行；建议仍为单批 64 MiB／600 秒，
2 MiB 终态预留、8 MiB 源码快照，C>=3 GiB、E>=4 GiB+32 MiB，
启动另留本批空间。当前授权不自动覆盖这批测试。

| 门槛 | 必须留下的证据 | 失败条件 |
|---|---|---|
| 静态目录等价 | 有界合成目录及已登记只读目录的路径集合、逻辑总量逐项相等 | 漏项、重复项、大小不一致 |
| 预算边界 | 上限下方/恰好上限/超一字节、写入前 additional、原磁盘底线 | 接受应拒绝的写入或更低底线 |
| 异常处理 | 权限/读取错误、消失、重解析点、异常传播的独立见证 | 静默跳过或未知状态继续 |
| 变化与新鲜度 | 受控追加、截断、新增/删除、日志增长的分阶段观测；跨次检查不复用旧大小 | 用过期总量允许继续 |
| 停止与终态 | 短内层限额的故障注入、所属进程清理、持久失败回执；外层真实保护始终启用 | 残留进程、丢失失败终态、自动重试 |
| 有界性能对照 | 原/新实现平衡顺序计时、原始样本、调用次数与相同计数 | 只给加速数字而无安全/等价证据 |

故障注入只对隔离测试对象使用受控时钟、文件系统故障或模拟容量；
不得真实耗尽 C/E 盘、触碰旧证据权限或降低实际外层监护保护。
并发变化不能用两个不同时间点的目录总量强行要求数值相等；需使用
可复现的事件序列及拒绝/停止断言，明确读写时序。

所有对照、负控、故障注入和剖析都计入同一单批预算，写入新的输出目录。
代码快照和旧证据绑定前后摘要，任何失败不自动修复重跑。

## 不在当前方案内

- 不去掉矩阵运算中的检查点，不减少真实磁盘余量检查频率。
- 不用永不过期缓存、纯估算总量或跳过未知文件来换取性能。
- 不重排/删除旧证据，也不通过改写旧结果目录布局获得漂亮对照。
- 不提升物理误差阈值、源码上限、总输出上限或单批时间。
- 不移植 GPU，不运行八射线、完整 66 背景矩阵或时间演化。

只有等价与故障控制通过并获得新的物理批次授权后，才讨论八射线 v2。
旧 v1 永久保留 TIMEOUT；候选通过也不能推翻旧记录，更不能取得 live
或 scientific payload 准入。
