# 主线 A：六阶段 Goal 与十轮执行协议

主线 A 的唯一父 goal 是“建立 Gaia 深空美术与知识层，同时保持现有 EIH、Newton N-body、2PN/Lense–Thirring 与 Kerr 物理内核不变”。六个阶段是这个父 goal 的六个可验收子目标；每个子目标必须留下代码、数据、来源和验证证据。

## 六个阶段 goal

| Goal | 目标结果 | 主要交付物 | 退出条件 |
|---|---|---|---|
| A1 合同与盘点 | 统一星座、星云、恒星的数据—美术—叙事—来源字段，并盘点首批对象 | contract、registry、coverage matrix、首批 4/12/6 对象、来源审计 | 数量、关系、来源字段和物理边界检查全部通过 |
| A2 常见星座 | 让猎户、北斗、仙后、天蝎具备 IAU 边界、连线、标签、艺术说明和来源卡 | 边界/星群数据、LOD 显示策略、四张星座知识卡、浏览器烟测 | 四个星座可从目录聚焦，边界不遮挡模拟，移动/桌面 LOD 稳定 |
| A3 星云美术 | 为 M42、M1、M8、M16、M20、M57 建立可追溯多波段艺术表现，并为其余六个对象保留目录标记 | 每图 manifest、波段映射、许可证状态、颜色/曝光校准说明 | 每个候选图像完成逐图权利核验；未核验资产不会进入 licensed |
| A4 恒星美术与介绍 | 将 Gaia 观测字段转成可解释的恒星外观和详细介绍 | 六颗首批恒星 profile、温度/光度/半径/不确定性说明、参数化 photosphere | 参数有限且可复现；介绍区分观测事实、模型和艺术推断 |
| A5 跨对象观测 | 把星座—星云—恒星—目录对象连成连续的观测路径 | relatedObject/relatedCatalog 导航、镜头聚焦、叙事过渡、关系完整性检查 | 任一关系点击都同步选择状态和相机焦点，断链检查为零 |
| A6 性能、版权与交付 | 在真实设备预算下完成最终验收和可复现发布 | 帧时/内存证据、来源与署名包、变更清单、release packet | 性能预算、来源可达性、许可证、构建和回归检查全部通过 |

## 当前执行批次：A2

A2 只处理表现层和知识层：

1. 固化四个首批星座的 IAU J2000 边界与星群连线的共同坐标合同。
2. 将边界、连线、标签接入同一显示门控，按 `qualityTier`、`lodTier` 和 cinematic profile 控制密度。
3. 为每个星座补齐中文/英文名称、形态叙事、可见季节、代表恒星和来源卡。
4. 以浏览器烟测验证目录选择、边界显隐、卡片字段和相机聚焦；记录桌面与移动档位。
5. 只在 A2 证据文件完成后，推进 A3 的逐图版权核验；不把候选图像提前标记为已授权。

A2 的下一次提交应优先包含：四个星座的知识卡字段、边界/连线的可见性快照、首批桌面/移动截图或 DOM 证据，以及一条可重复的 `node` 验证命令。

## 十轮的目的

这里的“十轮”是十个短反馈回路，不是十次无条件重写。每轮都要形成一个可检查增量：

1. 读取上一轮证据，锁定本轮单一验收问题。
2. 修改最小范围的数据、组件或来源记录。
3. 运行针对性测试、Lint、类型检查或来源可达性检查。
4. 做一次浏览器/可视化核对，确认艺术字段真的能被用户看到。
5. 更新阶段证据文件，记录通过项、剩余风险和下一轮入口。

十轮的具体分工为：

| 轮次 | 目的 |
|---|---|
| 1 | A2 边界与星群坐标冻结 |
| 2 | 边界/连线 LOD 和性能门控 |
| 3 | 四个星座标签、双语名称和叙事字段 |
| 4 | 四张星座知识卡与来源卡 |
| 5 | A2 浏览器烟测和可视化证据 |
| 6 | A3 六张星云候选图逐图权利审计 |
| 7 | 星云多波段编码、曝光和色彩说明 |
| 8 | A4 六颗恒星的 Gaia 介绍和参数化外观 |
| 9 | A5 关系导航、镜头同步和断链检查 |
| 10 | A6 性能、版权、构建和发布包总验收 |

每轮的目的，是缩小“资料正确、视觉可见、交互可达、来源可追溯、性能可接受”之间的差距；十轮结束时应得到可复现的发布证据，而不是只得到一组静态图片。

## 与广义相对论模拟的接口

主线 A 不改动核心积分器和相对论观测核。A4/A5 只读取已有的选择状态、观测视场、轨道和 Kerr/阴影结果，把它们作为叙事上下文；任何新的视觉参数都必须标记为 presentation-only。若需要改变物理方程、积分步长、PN 阶数或观测模型，应另开独立物理 goal，并在 A6 中做接口回归。
